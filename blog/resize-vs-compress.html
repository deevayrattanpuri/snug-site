Resize or compress? They are not the same thing

Both make the file smaller. They do it by removing completely different things, and picking wrong costs you quality you did not need to lose.

Sizing 8 September 2026 ·5 min read

People use the words interchangeably, and most of the time it does not matter. When a photo has to meet a specific requirement, it matters a lot.

Resizing changes the pixel count

A 4000 × 3000 photo contains twelve million pixels. Resize it to 2000 × 1500 and it contains three million — a quarter as many, because both dimensions halved. The picture is genuinely smaller now; shown at its natural size it occupies a quarter of the area it used to.

Resizing down is irreversible in practice. The discarded pixels are gone, and enlarging later only spreads the survivors over more space.

Compressing changes how the pixels are stored

Compression keeps all twelve million pixels and finds a more economical way to describe them. JPEG does this by simplifying detail the eye is poor at noticing. Push it gently and you will not see anything; push it hard and you get blocky squares and colour banding.

The dimensions do not change at all. A heavily compressed 4000 × 3000 photo is still 4000 × 3000.

When to use which

The situationDo this
A form specifies pixel dimensionsResize — there is no choice
A form specifies a file size onlyResize first, then compress
Dimensions are already right, file too bigCompress
A document scan that must stay legibleCompress — keep the resolution
Emailing holiday photosResize — nobody needs 4000 px in an inbox
A photo for printCompress gently, never resize down

Why order matters

If you only remember one thing: resize before you compress.

Compression quality is spent per pixel. Squeezing a twelve-megapixel photo into 200 KB forces an extreme quality setting because there are so many pixels to pay for. Resize to 1200 px wide first and the same 200 KB is spread across far fewer pixels, so each one can be described properly.

Same destination, dramatically different result.

The practical shortcut

Working this out manually means guessing, checking, and adjusting. Setting a target file size inverts it: you state the ceiling, and the tool finds the dimensions and quality that fit. Snug's target file size row does exactly that — and because it writes a new file, the original is still there if the trade-off was not worth it.

The short version

Resize changes how many pixels there are. Compress changes how they are stored. Resize first, always.
