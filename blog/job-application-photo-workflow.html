A workflow for sizing everything a job application asks for

One application, six uploads, six different sets of rules. Do it once, properly, and reuse it.

Workflow 14 April 2026 ·6 min read

A single application can want a photograph, a signature, a scanned certificate, proof of identity and a CV — each with its own dimensions, format and file size ceiling, each rejected individually. Doing this ad hoc at midnight before a deadline is how mistakes happen.

Step 1: collect every requirement first

Before touching a photo, write down for each upload: format, dimensions, minimum and maximum file size, and anything about content. Portals scatter these across several pages, and the minimum size in particular is easy to miss.

Ten minutes here saves every rejection that follows.

Step 2: capture everything in one sitting

Same light, same background, same session:

  • The portrait, against a plain light wall in indirect daylight
  • Your signature in dark ink on plain white paper
  • Every certificate and document, flat, shot square from above

Consistency makes the set look deliberate, and means one lighting decision covers all of it.

Step 3: build a master folder

Keep the untouched originals in one place, named clearly — portrait-original.jpg, signature-original.jpg, degree-certificate-original.jpg. Every submitted version gets made from these, never from another submitted version.

This is what stops generation loss: each export is one encode away from the original rather than five.

Step 4: produce one version per requirement

For each upload, from the master: crop to the required ratio, resize to the exact dimensions, convert to the required format, then bring it under the file size ceiling — in that order.

Name each output after where it is going: portal-photo-200x230-under-50kb.jpg. In three weeks, when the portal asks you to re-upload, you will know instantly which file it wants.

Step 5: check each one before uploading

  • Open it at 100% — is it legible, is it sharp?
  • Confirm the file size is inside both ends of the range
  • Confirm the dimensions are exactly what was asked
  • Confirm the format is what was asked

Step 6: keep everything, for a year

Applications get queried. Interview stages ask for the same documents again. A second application to a similar body wants the same photo at a slightly different size. Keep the masters and the outputs until the whole process is unambiguously finished.

Why keeping originals is the backbone of this

Every step above depends on the master files staying pristine. Tools that overwrite your original break the whole approach, because the second time you need a different size you are working from an already-compressed file.

Snug writes every result as a new file in Pictures/Snug and leaves the original alone, which makes it safe to generate as many versions as the application demands.

The short version

Collect every requirement first, shoot once, keep pristine masters, and export a separate named file for each upload.
